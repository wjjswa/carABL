# E10 — Five-class Root-Guided Cascaded Car Damage Classification

**Branch:** experiments/e10-five-root-cascade-20261107  
**Implementation:** carrepair/e10.py  
**Slurm DAG:** carrepair/e10_submit.py, scripts/submit_e10.sh, scripts/e10_slurm_job.sh  
**Results:** outputs/e10/ (separate from E8/E9)  

## Question and comparison

Does learning the five *damage-label-derived* parent categories first, then
training part-specific experts, improve eight-class prediction over E8's flat
fine-tuning or E9-C's single-stage joint hierarchical fine-tuning?

E10 **is a genuine test-time cascade**, not merely reusing a root encoder as
an eight-class model initialisation. The root model stays intact at inference,
and each trained expert handles only its two original labels. E9-C is the
independent single-stage eight-class baseline; E10 never loads E9-C weights.

Original image-level labels (exactly as in the immutable carABL manifest):

| Root stage label | Original data labels | Stage 2 |
| --- | --- | --- |
| bumper | bumper_dent, bumper_scratch | bumper expert: dent / scratch |
| door | door_dent, door_scratch | door expert: dent / scratch |
| lamp | head_lamp, tail_lamp | lamp expert: head / tail |
| glass | glass_shatter | direct glass_shatter |
| unknown | unknown | direct unknown |

Exactly eight outputs: bumper_dent, bumper_scratch, door_dent, door_scratch,
glass_shatter, head_lamp, tail_lamp, unknown. Glass and Unknown have no expert.

**Important ontology limitation:** Root classes were derived from an image
classification label, **not the location of a damaged part**. Images may show
multiple components and labels may be imperfect physical-part proxies.
The trained unknown class represents the dataset's labelled catch-all;
**it does not validate rejection of unseen open-world categories.**

## Architecture and initialisation

**Stage 1: Five-class supervised Root.**

1. Load the pinned **Majorburn/yolov11-carparts-seg** checkpoint: a YOLO11
   model trained to segment 23 car parts (not damage regions). Verify SHA256.
2. Copy the entire YOLO11 backbone through SPPF and C2PSA, discarding the
   original segmentation neck/head.
3. Attach Global Average Pooling and a new five-way linear classifier.
4. Full fine-tune the backbone and root head using **all eight original
   training labels remapped to the five parents**.
5. Select by validation Macro-F1, with patience 30, min_delta 0.001.
6. Save root/seedN/**best_root.pt** and resumable last.pt. Held-out root
   metrics are for diagnostics and never used to train or select models.

**Stage 2: Three independently full-fine-tuned experts.**

For each seed N, train bumper, door and lamp expert **from the root seed N
best backbone**, NOT from E9-B or from an eight-class checkpoint. Experts
get **fresh two-class heads**. Each expert trains exclusively on its own
original class images, preserving the train/validation/test splits, and
updates its private backbone and head. The completed Stage 1 Root model is
never overwritten or modified.

- bumper: 2-class dent/scratch
- door: 2-class dent/scratch
- lamp: 2-class head/tail

Each expert saves experts/NAME/seedN/best.pt and last.pt. Stage 2 test
metrics are conditional on the **ground-truth** parent and are reported as
diagnostics, not deployed end-to-end cascade accuracy.

**Stage 3: Eight-class cascade test evaluation.**

On the same fixed eight-class test set (226 images in the current prepared
manifest), load same-seed Root and the three same-seed experts. Evaluate
the models without further adaptation:

- **Hard routing**: choose the highest-probability root; if bumper/door/lamp,
  run its matching expert and choose its highest-probability child; if
  glass/unknown, output that label directly. Production hard inference
  needs only one expert. Offline comparison may compute all expert logits
  once to compare hard and soft without repeated preprocessing.
- **Soft routing**: run all three experts and multiply their child
  probabilities by the corresponding root probabilities. Glass/Unknown are
  direct root probabilities. Sum of the eight probabilities equals one.

Example: P(door_scratch) = P_root(door) * P_door_expert(scratch). The
canonical class mapping is in carrepair/e10.py:build_joint_probabilities.

Report complete hard and soft eight-way accuracy/Macro-F1, eight-class
Precision/Recall/F1/support and confusion matrices. Log per-image root
prediction, final hard/soft predictions, confidence, and error source:
wrong root versus correct root but wrong expert. Error decomposition counts
all failed hard predictions without double-counting. Save probabilities.npz.

For fair model comparisons, E8 8class / E9-C / E10 use the *same original
eight-class held-out test items*. Stage 1 root accuracy (five classes), expert
accuracies (two classes, filtered test subsets), and end-to-end eight-class
accuracy (all test images) are **not interchangeable**.

## Protocol (both training stages)

- Immutable dataset: Kaggle Car Damage Assessment, via the existing
  data/prepared/manifest.csv and data/kaggle (no re-split).
- Seeds: 0, 1, 2; Root and three matching experts per seed.
- Image size: 384 x 384, aspect-ratio-preserving padding.
- Training augmentation: random horizontal flip; ColorJitter brightness 0.15,
  contrast 0.15, saturation 0.10, hue 0.025 with probability 0.4. No heavy
  crop that might remove body-component context.
- AdamW, backbone LR 1e-4, head LR 1e-3, weight decay 1e-4.
- Batch size 16; cosine LR decay across max 300 epochs.
- Early Stopping: validation Macro-F1, patience 30, min_delta 0.001,
  separately in every Root and expert training; max 300 epochs. A new
  best.pt is written on any true improvement; patience reference resets
  only on improvement greater than min_delta.
- Overfitting warnings are diagnostic and separate from the early stop.
- Deterministic epoch/seed reseeding, resumable last.pt and provenance
  checks. Only the best-validation checkpoint is used on test.
- GPU: 1 per job, 8 CPUs, 32 GB RAM. Slurm 72h per job requested by
  default; subject to site limits.
- **No scratch, extra class balancing or loss-weight tuning** in this
  first comparison. These are candidates for later ablations.

### Submit dependencies automatically

Dry-run (no queue changes):

    bash scripts/submit_e10.sh --config configs/e10_artemis.yaml

Submit the actual experiment DAG:

    bash scripts/submit_e10.sh --config configs/e10_artemis.yaml --submit

The command creates **15 GPU jobs**: 3 Root jobs, 9 expert jobs and 3
final cascade evaluations. For each seed, root -> [bumper, door, lamp]
via Slurm afterok dependencies, then all three -> evaluation. Experts
cannot start before the matching Root succeeds; evaluation cannot start
before all same-seed experts finish.

On the Artemis GPU queue, a job in PD state with reason Dependency or
QOSMaxGRESPerUser is normal until prerequisite jobs finish or GPU quota
becomes available.

Check exact job names and IDs:

    squeue -u "$USER" -o "%.12i %.43j %.2t %R"
    sacct -u "$USER" --starttime 2026-11-07 \
      --format=JobID,JobName%35,State,ExitCode,Elapsed

Watch logs:

    ls -lh logs/e10
    tail -f logs/e10/carABL-e10-root-s0-<JOB_ID>.log

**Do not blindly run the submission command a second time after
cancellation.** The registry logs/e10_submissions.json records IDs and
never retries a canceled/failed job automatically. If a task fails or
is canceled, inspect its partial history and last.pt; use the individual
module with --resume for a deliberate recovery. For a clean rerun, create
a separate output root and a new submission registry/config.

If the registry contains a previously submitted job that is canceled,
its dependents may remain pending with DependencyNeverSatisfied until
canceled; investigate with sacct and scontrol.

## Scientific caveats

- Comparing E10 versus E9-C answers a *pipeline design* question. E10 uses
  extra Root + expert optimisation time and substantially more parameters.
  It does **not** isolate the effect of hierarchy alone; match compute
  in a follow-up ablation if claiming improvements from staged learning.
- Hard routing errors propagate from root to leaves. Soft routing trades
  extra compute for probability mixture; probabilities may need calibration
  if deployment requires trustworthy confidence.
- Full fine-tuning with small expert subsets may overfit. Keep each expert's
  validation and test per-class metrics, early stop, and loss curves visible.
- True damage localisation is not evaluated: labels identify a damaged
  category, not a bounding box/mask for that damage.
- The Majorburn original segmentation checkpoint is distributed under
  AGPL-3.0 according to the upstream model card; review licensing before
  commercial deployment and verify the source before deserialising .pt.
