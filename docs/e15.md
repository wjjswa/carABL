# E15-A/B: single-stage direct SigLIP2 eight-class assessment

## Research question
Does direct eight-way fine-tuning of the *same* SigLIP2 Base 224px encoder
outperform the six-way E14-D + E9-B bumper/door cascade? Does unfreezing
the entire backbone improve upon fine-tuning only its final four blocks?

| Variant | Head | Vision parameters | Inference |
| --- | --- | --- | --- |
| E15-A | new eight-way linear head | final four blocks + final norm | one classifier |
| E15-B | new eight-way linear head | **all** vision parameters | one classifier |
| E14-D reference | six-way head | final four blocks + final norm | six-way root + separately trained E9-B expert |

Original eight classes, ordered identically to E9/E11: bumper_dent,
bumper_scratch, door_dent, door_scratch, glass_shatter, head_lamp,
tail_lamp, unknown. The **unknown** label here is the dataset's existing
eighth class: this is **not** an open-set or OOD detector.

The training/validation/test images and groups are unchanged from E11:
1050/229/226, seeds 0,1,2. Both E15 variants use SigLIP2
`google/siglip2-base-patch16-224`, 224px, training augmentation matching
E14-D, learning rates backbone=1e-5/head=1e-3, AdamW, cosine annealing,
batch size 16, 300 maximum epochs and validation macro-F1 early stopping
patience 30. No second-stage expert is loaded or trained.
All test metrics are computed only in `evaluate`, after checkpoint
selection. Historical test reuse makes this exploratory.

## Artemis: create isolated E15 worktree

Never checkout the new branch inside the running E13/E14 directory. First
update the Git repository then create a separate worktree:

```bash
cd /mnt/nfs2/engdes/jw840/carABL-e13e14
git fetch origin
git worktree add ../carABL-e15 origin/experiments/e15-direct-siglip2-20261109
cd ../carABL-e15
source scripts/artemis_env.sh
python -m pip install -e '.[foundation,test]'
```

Use the **already downloaded** E14-D SigLIP2 snapshot and E11 manifest.
If you used the ungated E14 config, run:

```bash
python scripts/create_e15_artemis_config.py \
  --previous ../carABL-e13e14/configs/e14_ungated_artemis.yaml
```

If your actual E14 configuration is instead
`configs/e13e14_artemis.yaml`, replace the `--previous` path.
If the model was not downloaded yet, download it on the login node using
the existing E14 downloader before generating E15 configuration.

## Preflight and direct submission

```bash
python -m carrepair.e15 preflight --config configs/e15_artemis.yaml --model-smoke
bash scripts/submit_e15.sh --config configs/e15_artemis.yaml
bash scripts/submit_e15.sh --config configs/e15_artemis.yaml --submit
squeue -u "$USER"
```

The submitter writes `logs/e15_submissions.json` and creates for each
seed/variant a train job plus an `afterok` dependent evaluation job.
**No job is actually queued until --submit.** For a 3-day walltime limit
use `--time 3-00:00:00`; E15-B may need more memory/time depending on
actual Artemis GPU. Do not submit repeated jobs until reading the registry
and logs. For a verified interrupted train, `--resume` is supported
using `last.pt`; the same registry will not resubmit a recorded job.

## Aggregate and archive

```bash
python -m carrepair.e15 aggregate --config configs/e15_artemis.yaml
# Only if E14-D reference test predictions are available:
python -m carrepair.e15 aggregate --config configs/e15_artemis.yaml \
  --reference-e14 /mnt/nfs2/engdes/jw840/carABL-e13e14/outputs/e14_ungated
tar -czf /mnt/nfs2/engdes/jw840/carABL_E15_AB_results.tar.gz \
  --exclude='*.pt' -C outputs e15
```

Reported artifacts: individual seed accuracy/macro-F1, mean and sample
standard deviation, per-class precision/recall/F1, confusion matrices,
per-image probabilities, plots, and optional paired E14-D correction counts.
Only `best.pt` contains the selected trained model. `last.pt` contains
large optimizer state for resumption. A metrics archive intentionally excludes
both weights; transfer `best.pt` separately for demo inference.

## Interpretive limits
This is classification of one image into one of the eight known dataset
labels; it does not localise multiple damage instances and must not be
described as instance detection or unknown-category rejection. No accuracy
claim can be made before Artemis training and held-out evaluation complete.
