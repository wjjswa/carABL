# E9: Part transfer, binary Bumper/Door, and hierarchical damage recognition

GitHub branch: experiments/e9-part-hierarchy. Results: outputs/e9/.

## Source checkpoint and data

The sole pretrained source is Majorburn/yolov11-carparts-seg best.pt, pinned to
Hugging Face revision f26ca7107b40dd9a385ea82fd2fef8a3d6044dc7.
The original model segments 23 car parts, **not** damage regions. Its model
card reports mAP50=71% for its own part task, not a verified score on Kaggle.

The input data are the existing immutable, group-disjoint
data/prepared/manifest.csv and data/kaggle images from Kaggle Car Damage Assessment.
No data are downloaded or re-split by these scripts.

### E9-A: zero-shot transfer without target training

Evaluate only bumper_dent, bumper_scratch, door_dent and door_scratch **test**
images. Map part-segmentation model output names:
- Bumper = back_bumper, front_bumper
- Door = back_door, back_left_door, back_right_door, front_door,
  front_left_door, front_right_door

For each image, predict the Bumper/Door with the highest segmentation
instance mask area × confidence. If neither part is detected, record abstain.
This heuristic cannot locate the damaged area or know which of several visible
parts is damaged. Report image-level strict accuracy (abstain wrong), coverage,
accuracy only on classified cases, both-part detections, each-class recall,
and confusion matrix. No test labels are used for model selection or adaptation.
This is not 300-epoch training: E9-A is direct pretrained inference.

### E9-B: 2-class supervised full fine-tuning

Remap 4 damage labels to Bumper (bumper_dent + bumper_scratch) vs Door
(door_dent + door_scratch). Train only these 4 original classes' *training*
images; use their validation and test subsets for evaluation. Drop all other
classes from this E9-B task. Transfer the same pretrained YOLO11 encoder (through
C2PSA), replace original segmentation head with global-average pooling + a
2-class head, and fully fine-tune every backbone parameter and the head.
This is not part-mask guided learning; it is an image-level classifier.

### E9-C: hierarchical original 8-class full fine-tuning

Train using ALL eight original classes including unknown. Shared fully
trainable pretrained encoder and three heads:
- Root part: bumper, door, other
- Conditional bumper/door damage: dent, scratch
- Conditional other type: glass_shatter, head_lamp, tail_lamp, unknown

The joint probabilities are products, e.g.
P(door_scratch)=P(door)*P(scratch | door_or_bumper).
Use the negative log likelihood of the joint correct class as the loss,
training the entire shared backbone and the relevant branch each sample.
Evaluate 8-class end-to-end accuracy/macro-F1/confusion, root 3-way accuracy,
root accuracy on the SAME four Bumper/Door categories as E9-A/B (including
misrouting to Other as incorrect), and true-parent conditional branch
accuracy/confusion (diagnostic only, not deployed).
The catch-all unknown is a *trained eighth class*, not unseen novelty. The
root label "other" means "one of the four remaining dataset labels", and
does NOT establish that the visibly damaged physical component is not
a door or bumper. This weak supervision can introduce label noise.

## Shared training protocol

Up to 300 epochs, all eligible training data, seeds 0/1/2, batch16, size384,
AdamW, backbone LR 1e-4, head LR 1e-3, cosine schedule, mild flip/jitter,
context-preserving padding (no aggressive crop). No training-fraction sweep,
no scratch/control model. **Early stop** after 30 consecutive validation
Macro-F1 epochs without improvement over 0.001 (the reference is the last
significant best); still retain the true highest-F1 checkpoint. This means
300 epochs is the maximum, not a guaranteed duration. Log deterministic training and
validation loss/accuracy/macro-F1 every epoch, warning flags for sustained
train/val divergence, and save best.pt (highest validation macro-F1) plus
last.pt (resumable). Evaluate held-out test images once after training, with
the best-validation checkpoint.

## Safe Artemis setup

DO NOT switch the existing checkout while E6, E7 or E8 jobs use it.
Create a new worktree, leaving the original data immutable:

    cd /mnt/nfs2/engdes/jw840/carABL
    git fetch origin
    git worktree add /mnt/nfs2/engdes/jw840/carABL-e9 origin/experiments/e9-part-hierarchy
    cd /mnt/nfs2/engdes/jw840/carABL-e9
    source scripts/artemis_env.sh

Create a local config pointing at the original data (not checked into GitHub):

    python - <<'PY'
    import yaml
    cfg = yaml.safe_load(open("configs/e9.yaml"))
    cfg["manifest"] = "/mnt/nfs2/engdes/jw840/carABL/data/prepared/manifest.csv"
    cfg["data_root"] = "/mnt/nfs2/engdes/jw840/carABL/data/kaggle"
    with open("configs/e9_artemis.yaml", "w") as f:
        yaml.safe_dump(cfg, f, sort_keys=False)
    PY

Do not reinstall the editable package into the shared Conda env during
active E6/E7 jobs. Running python -m from the E9 checkout imports its own
carrepair package first. Existing packages should be reused.

Download and verify the pinned model on a login or transfer node with
Hugging Face access. External PyTorch checkpoints may deserialize untrusted
code; verify the publisher and license before use.

    python -m carrepair.e9 download --config configs/e9_artemis.yaml
    OMP_NUM_THREADS=1 python -m pytest -q tests/test_e9.py
    python -m compileall -q carrepair
    bash -n scripts/e9_slurm_job.sh scripts/submit_e9.sh

Submission (1 zero-shot GPU job + 6 training GPU jobs), preview first:

    bash scripts/submit_e9.sh --config configs/e9_artemis.yaml
    bash scripts/submit_e9.sh --config configs/e9_artemis.yaml --submit
    squeue -u "$USER"

One GPU, 8 CPU, 32GB RAM; 72-hour allocation is requested but subject to
local cluster limits. If batch size does not fit, adjust a separate config
*before* submission. Jobs may wait in QoS GPU queues. Registry
logs/e9_submissions.json skips recorded jobs; it does not retry failures.
Investigate logs/e9/*.log and checkpoints before attempting deliberate recovery.

Once all six training jobs finish:

    python -m carrepair.e9 aggregate --config configs/e9_artemis.yaml
    cat outputs/e9/trained_mean_std.csv
    cat outputs/e9/per_class_mean_std.csv
    cat outputs/e9/zero_shot/metrics.json
    tar --exclude='*.pt' -czf carABL_e9_results.tar.gz -C outputs e9

### Output tree

- outputs/e9/zero_shot/: part_predictions.csv, metrics.json, provenance.json
- outputs/e9/binary/seedN/: best.pt, last.pt, history.csv, curves,
  per_class.csv, test_predictions.csv, confusion_matrix.json, metrics.json
- outputs/e9/hierarchical/seedN/: same plus root_confusion_matrix.json
  and root/conditional metrics in metrics.json
- outputs/e9/trained_per_seed.csv, trained_mean_std.csv,
  per_class_per_seed.csv, per_class_mean_std.csv

Do not directly compare E9-C's 8-class overall accuracy with E9-A/B's
2-class accuracy; compare appropriate shared Bumper/Door test slices or
root classifications for fair claims. Results are unavailable until Artemis
actually runs. Model card is AGPL-3.0; check licensing for downstream use.


## Updated Early Stopping and new Artemis submission (2026-11-07)

Early stopping is enabled for **E9-B binary** and **E9-C hierarchical**
training only: validation Macro-F1, patience 30, min_delta 0.001.
Overfitting alarms still run separately. E9-A zero-shot uses no epochs and
has no early stopping.

The changed config and checkpoint resume state are incompatible with prior
E9 training outputs. **Do not overwrite active E9 working directories or reuse
old `outputs/e9` results.** Create a fresh
`carABL-e9-es` worktree at the updated branch (after `git fetch origin`),
generate a fresh local config with absolute paths to the original manifest
and images, verify tests, download or copy the same pinned checkpoint, and
preview/submit jobs from that new directory. To avoid paying for old and new
versions concurrently, identify old jobs by their full job names first:
`squeue -u "$USER" -o "%.12i %.50j %.2t %R"`, then cancel only the
specific old E9 IDs with `scancel ID...`. Check E8 and E6/E7 IDs carefully.
